# Techniques for difficult requirement exploration

Use these techniques within the main skill's decision tree. The main file owns waiting and completion conditions; this reference changes how questions are formed, not when the interview ends.

Choose the starting point that matches the unresolved intent:

- **Dissatisfaction:** establish what falls short, how it affects the user, and what a better result would let them do. Separate observed problems from proposed solutions.
- **Abstract preference:** first elicit the user's own experience or desired effect. When that is difficult to express, contrast examples without marking one as preferred. Ask what makes an example fit better, then derive observable criteria from the answer.
- **Uncertain direction:** establish the desired outcome and compare plausible routes and trade-offs. Help the user discover a preference instead of inventing one for them.
- **Existing plan:** examine the assumptions connecting the proposed means to the goal. Use a relevant counterexample or constraint to reveal an overlooked choice.

When an answer remains broad, follow its implications to the next decision. Ask only follow-ups that could change the result. A small example or reversible sample can make an abstract choice answerable; label it as exploratory and retain alternatives until the user chooses or delegates. Agreement with an example does not establish unrelated requirements or factual feasibility.
